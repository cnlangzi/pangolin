# Admin UI internationalization (i18n)

The admin panel is server-rendered: askama templates + htmx. The
interface language is therefore resolved **on the server**, per
request, and handed down to the templates as a `lang` value.

There is no client-side dictionary to apply after an htmx swap, so a
partial refresh never flashes the wrong language.

## Where the files live

| File | What it is |
| --- | --- |
| `crates/admin/i18n/en.json` | The English catalog — the source of truth for every key. |
| `crates/admin/i18n/zh-CN.json` | The Simplified Chinese catalog. Translated area by area; the areas that are done are listed in `COMPLETED_AREAS`. |
| `crates/admin/src/i18n/mod.rs` | The `Lang` enum, the lookup, the cookie, the `Accept-Language` negotiation. |
| `crates/admin/src/i18n/catalog.rs` | The embedded catalogs, the key shape, the area list. |
| `crates/admin/src/i18n/quality.rs` | The gates that keep the Chinese catalog from rotting into a machine translation. |
| `crates/admin/templates/components/_lang_switcher.html` | The language switcher (a `<details>` dropdown, no JavaScript needed). |

Both catalogs are embedded at compile time with `include_str!` and
parsed once per process into a `HashMap<String, String>`.

## The key shape

A key is `area.item`, lower-case snake_case, at least two segments:

```
nav.sites
sites.delete.confirm
time.seconds_ago
common.provider.cloudflare.label
```

The **area** is the part before the first dot. The list of areas is
closed — a key in an undeclared area is a typo, and the gate test
turns it red:

```
nav      common   login    dashboard  components  sites   domains
tunnels  certs    dns      ratelimit  settings    logs    bots
referers traffic  time     activity   lang        js
```

A catalog value is plain UTF-8 text. It must **not** contain HTML:
askama escapes `{{ }}` by default, so a tag in a value would show up
as visible text.

Technical identifiers stay in the template — they are not prose and
translating them would break the operator's grep: `DNS`, `ACME`,
`TLS`, `HTTP-01`, status codes, provider keys, bot ids, file paths,
host names, and the brand name `Pangolin`.

## The glossary (术语表)

The glossary is the **single** English → Chinese dictionary of the
admin UI. Every translation issue reads it before it writes a single
line, and every string has to use the Chinese name the glossary
gives: the same word must not be translated two ways in two pages.

The table is normative in both directions:

- a new term is **appended**, and the translation that uses it
  follows;
- an existing term may be **changed** — but only together with every
  string in the repository that uses the old name. The glossary is not
  a wish list, it is a constraint: a changed row means a changed
  `crates/admin/i18n/zh-CN.json` and a PR description that names the
  affected keys.

The 中文 column is the only approved wording. `概览` for `Overview`
and `仪表盘` for `Dashboard` are two different things, and mixing them
up is how an interface starts to feel untranslated.

## The Chinese writing rules (中文行文规则)

The glossary decides *which* word to use. These six rules decide how
to write the sentence around it. They are what "reads like Chinese"
means concretely — a machine can check three of them, the rest are
reviewed by a human.

1. **A label or a button is a noun or a verb of two to six
   characters — never a sentence.** “新建站点” (*create site*), not
   “创建一个新的站点” (*create a new site*). A label that needs a
   sentence is a paragraph, and a paragraph in a table cell is a bug.
2. **An empty state is “暂无 X”, never “没有 X”.** A count is “共 {n}
   条” — never “{n} 条(s)”, and never a plural spelled out in
   parentheses.
3. **Half-width punctuation becomes full-width** — `(` `)` `,` `?` `!`
   `;` `:` become `（）` `，` `？` `！` `；` `：`. Between a Chinese
   character and a Latin word, a number or a `{placeholder}` there is
   **one half-width space** (“DNS 记录”, not “DNS记录”). A label
   carries no full stop at its end; a sentence in a paragraph does.
4. **No translationese.** Not “无效的 X” (*an invalid X*) but “X 错误”
   or “X 不正确”; not “点击此处…” (*click here…*) but the verb
   itself. Chinese sentences name the action, not the link.
5. **A placeholder keeps its name and may move.** `{name}` stays
   `{name}`; only its position follows the Chinese word order — "Delete
   site {name}?" becomes “确定删除站点 {name}？”.
6. **What is not translated** (see the list below): a string that is
   a technical identifier keeps its English spelling.

### The do-not-translate list (不译清单)

These keep their English spelling in every catalog:

- protocol and algorithm abbreviations: `DNS`, `ACME`, `TLS`, `RSA`,
  `ECDSA`, `PEM`, `HTTP-01`, `DNS-01`;
- HTTP methods: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`;
- HTTP status codes;
- provider keys and bot ids;
- the DNS providers' credential field names — `Access Key ID`,
  `Access Key Secret`, `Secret ID`, `Secret Key` — they are the
  field names of the cloud vendor's own console;
- the rate limit rule's enumeration values — `global`, `whitelist`,
  `blacklist` — they are written to the database and matched at
  request time;
- domain names, host names and file paths;
- the brand name `Pangolin`;
- third-party site names: `ipinsights.io`, `GreyNoise`, `AbuseIPDB`,
  `Scamalytics`, `Cloudflare`, `ipwhois.app`, `ipinfo.io`;
- HTTP header names: `Referer`, `User-Agent`;
- diagnostics — a message that quotes the underlying error, e.g.
  `Database error: {e}`.

A key on this list has the **same value** in every catalog. The
quality gate knows about the ones that are translated so far: a
Chinese value that is byte for byte the English one has to be
registered in `IDENTICAL_OK`, which is what makes a new untranslatable
key a deliberate decision instead of an accident.

A diagnostic that is quoted **inside** a Chinese sentence still has to
follow rule 3 — so it belongs in a placeholder. The substituted text
is not part of the catalog value and is not checked:

```json
"settings.error.backend": "后端错误：{error}"
```

A literal `connection refused: port 8080` pasted into the Chinese
text would fail the punctuation gate on its second colon.

## The lookup

```rust
lang.t("nav.sites")                                  // → Cow<str>
lang.tf("sites.delete.confirm", [("name", name)])    // → String
```

`t()` returns a borrowed string when the key is in the catalog. `tf()`
substitutes the named `{placeholders}` of the catalog value.

The **fallback chain** is fixed:

1. the target language's catalog,
2. the English catalog,
3. the visible marker `[missing:key]`, plus one `log::error!` line.

Nothing in the i18n module panics — a panic inside a request handler
becomes a 500.

## The language of a request

`admin::handle` resolves the language once per request:

1. the `pangolin_lang` cookie (the operator's explicit choice),
2. the `Accept-Language` request header — the highest-weighted
   supported tag wins, `zh` / `zh-CN` / `zh-Hans` map to `zh-CN` and
   `en` / `en-US` map to `en`,
3. the default, `en`.

The resolution never writes the cookie back — only the switcher does.

## The switcher

`GET /lang/{code}` writes the cookie and redirects back to the `next`
parameter (or `/`).

- The endpoint is **public**: the login page shows the switcher, and
  nobody can sign in yet.
- An unknown code is a **404**, not a silent fall back to the
  default.
- The `next` parameter is sanitised: it must be a same-site absolute
  path. `//evil.com` and `/\evil.com` are both resolved by a browser
  as a URL to another host, so they are rejected.

The switcher is only rendered when `Lang::available().len() >= 2` —
a dropdown with one entry is noise. The moment a second catalog has
text in it, the switcher appears; nothing else has to change.

Every language is listed in **its own** name (`English`, `简体中文`),
so an operator who cannot read the current one can still find theirs.
A language's own name is not translated, which is why the `lang` area
is empty in both catalogs: the switcher has no prose of its own.

## Adding a string

Three steps, in this order:

1. **Add the key** to `crates/admin/i18n/en.json` with the English
   text.
2. **Reference it** in the template: `{{ lang.t("area.item") }}`, or
   `{{ lang.tf("area.item", [("name", site.name.as_str())]) }}` when the
   text has a placeholder.
3. **Add the translation** to every catalog that is not empty.

A template struct needs a `pub lang: Lang` field, and the route
handler that builds it needs a `lang: Lang` parameter — see
[the template guide](./template-guide.md).

## Adding a language

1. **Write the catalog**: `crates/admin/i18n/<code>.json`, a flat
   `"key": "text"` object. Start from `en.json` — a key that is
   missing falls back to English, so a partial translation is
   allowed, but the completeness test asks for the whole area before
   it is declared complete.
2. **Add the variant** to the `Lang` enum in
   `crates/admin/src/i18n/mod.rs`, with its BCP-47 `code()`, its
   native `display_name()`, and its `from_code()` arm — the arm is
   what maps the browser's `Accept-Language` tags to the language.
3. **Embed the catalog** in `crates/admin/src/i18n/catalog.rs`: an
   `include_str!` constant, a `OnceLock`, and a `catalog_for()` arm.

Nothing else has to change: the switcher lists the languages whose
catalog is not empty, the cookie carries the code, and the negotiation
follows `from_code`.

## The gate tests

```bash
cargo test -p admin --lib i18n
```

- `catalog_keys_match_code_references` — every key the code
  references is in the catalog, and every key in the catalog is
  referenced. A typo in a key name turns this red.
- `catalog_completeness` — a translation may not invent a key the
  English catalog does not have, and an area that is declared
  complete has to be complete in every catalog.
- `every_catalog_key_is_well_formed` — every key matches the key
  shape and names a declared area.

### The Chinese quality gates

`crates/admin/src/i18n/quality.rs` holds the gates that keep the
Chinese catalog from rotting into a machine translation. They check
what a machine *can* decide; whether the Chinese is good is reviewed
by a human, against the glossary above.

- `no_chinese_string_is_left_untranslated` — a Chinese value that is
  byte for byte the English one has to be registered in
  `IDENTICAL_OK`. The whitelist is keyed, not valued: a new key that
  carries an untranslatable string has to be registered once, on
  purpose.
- `chinese_strings_use_full_width_punctuation` — a Chinese value may
  not contain half-width `(` `)` `,` `?` `!` `;` `:`.
- `chinese_strings_space_out_latin_words` — a Chinese character glued
  to a Latin word, a number or a placeholder (“DNS记录”, “共3条”) is a
  failure; “DNS 记录” is not.
- `long_chinese_strings_are_reported` — a value with more than 20
  Chinese characters is *reported*, not rejected: some sentences are
  naturally long, and a hard limit would push the translator into
  writing an incomplete sentence just to pass the test. libtest
  swallows the output of a passing test, so the report only shows up
  with `--nocapture`:

  ```bash
  cargo test -p admin --lib i18n::quality -- --nocapture
  ```

A value that only contains ASCII is exempt from the punctuation and
the space gate — a technical identifier has no Chinese punctuation to
convert — but it still has to be whitelisted for the first one.

The gates read the shipped catalog, so they can only ever be
exercised by the data they are checking. The predicates behind them
therefore have their own tests, against synthetic values: a predicate
that stops classifying Chinese as Chinese turns
`the_punctuation_predicate_sees_half_width_punctuation` red instead of
silently emptying the gate.

## `COMPLETED_AREAS`

`crates/admin/src/i18n/catalog.rs` holds a `COMPLETED_AREAS`
constant: the list of areas whose translation is complete. It starts
empty.

A translation issue adds its areas to the list once every key of the
area exists in every catalog. The completeness test then fails if one
of those keys goes missing — so "translated" cannot silently rot into
"half translated".

## The client-side script

`assets/app.js` reads the strings it needs from
`window.__PANGOLIN_I18N`, a dictionary the base layout renders into
the page:

```html
<script>window.__PANGOLIN_I18N = {{ lang.js_dict()|safe }};</script>
```

The dictionary is built in Rust from the same catalog, so the script
and the server always speak the same language.
